# Бриф для нового дизайна Alias Online

Документ для генерации нового дизайна (через любой UI-генератор).
Здесь — **что за продукт, какие нужны экраны, что на каждом, дизайн-система и
требования к адаптивности**. Сам творческий промт (стиль, настроение, референсы)
дописывает заказчик отдельно — здесь только фактура проекта.

Источник существующего наброска: `project-context/New-design/Alias Online - Bold.html`
(многоэкранный React-canvas). Реальный код: `apps/web` (Next.js).

---

## 0. TL;DR для дизайнера

- Игра **Alias** (объясни слово, не называя). Два режима: **онлайн** (каждый со
  своего телефона, реалтайм) и **локально** (одно устройство на компанию).
- Нужно **14 экранов** (см. §4), каждый в **desktop + mobile**, в **тёмной и
  светлой** теме.
- **Самое важное и самое больное — адаптивность.** Дизайн обязан хорошо
  выглядеть на **мобиле, 1366, 1920 и 2560** одновременно. На больших экранах
  НЕ должно быть «мелких элементов» и «кучи пустого места». Подробно — §3.
- Стиль уже задан токенами (§2): тёмный «чернильный» фон, мятный акцент,
  крупная типографика Manrope + моно-акценты JetBrains Mono.

## 1. Технический контекст (влияет на дизайн)

- **Стек:** Next.js (App Router) + React + Tailwind CSS v4. Дизайн ляжет в JSX +
  utility-классы и CSS-переменные. Значит: дизайн-токены = CSS-переменные,
  компоненты переиспользуемые.
- **Тема:** есть переключатель **тёмная/светлая**, тёмная по умолчанию. Любой
  экран должен быть нарисован в обеих темах (значения — §2).
- **Без регистрации:** пользователь анонимный (кука), экранов логина/профиля
  НЕТ.
- **Локализация:** интерфейс на русском. (В наброске местами проскакивает
  английский в «ярлыках» — это допустимо как стиль, но основной текст русский.)
- **Иконки:** проект использует `lucide-react`. Дизайнить под этот набор
  (wifi, smartphone, qr-code, users, clock, check, x, play, pause, trophy,
  crown, trash, plus, arrow-right, settings, refresh и т.п.).

## 3. ⭐ Адаптивность — главное требование

Прошлая боль: на 2560 элементы были мелкими и оставалась «куча пустого места»,
а на 1920 контент не помещался без прокрутки. Новый дизайн должен решать это
по правилам ниже.

### 3.1 Целевые разрешения (рисовать макеты под каждое)

- **Mobile:** 360–430px ширины (основной телефон 390px).
- **Tablet:** ~768–1024px.
- **Laptop:** 1280–1440px.
- **Desktop FHD:** 1920×1080.
- **Desktop QHD:** 2560×1440.

### 3.2 Правила масштабирования

1. **Текучая типографика.** Крупные заголовки задавать через `clamp()`, чтобы
   плавно росли от мобилы до 2560 (а не были фиксированными «мелкими»).
2. **Контент растёт вместе с экраном.** Контейнеры расширяются по брейкпоинтам
   (например 1280 → 1600 → 2040 → 2200), отступы и размеры элементов тоже
   увеличиваются на 1920/2560 — не оставлять «мобильные» размеры на огромном
   мониторе.
3. **Нет вертикальной пустоты.** Короткие экраны (hero, лобби) на больших
   мониторах **центрировать по вертикали** или заполнять контентом, чтобы не
   висел пустой низ. На 1920 ключевые элементы (кнопки и их подписи) должны
   помещаться **без прокрутки**.
4. **Нет горизонтальной пустоты.** На 2560 не оставлять огромные пустые поля по
   бокам — расширять контент-область и/или раскладку (2-колоночные hero,
   многоколоночные сетки).
5. **Реальные единицы под крупные экраны.** Для брейкпоинтов выше 1536 в Tailwind
   использовать `min-[1920px]:` и `min-[2560px]:` (или ступенчатый рост базового
   размера). Учитывать, что из-за полосы прокрутки 2560-монитор может отдавать
   ~2543px — пороги ставить с запасом.
6. **Мобила — приоритет читаемости.** Одна колонка, крупные тап-зоны (кнопки
   ≥48px), декоративные иллюстрации можно скрывать.

### 3.3 Что сдавать по каждому экрану

Для **каждого** экрана из §4: **desktop-макет + mobile-макет**, и оба — в
**тёмной и светлой** теме. Желательно показать, как ведёт себя на 1920 и 2560
(масштаб/раскладка), а не только на 1280.

## 5. Что на каждом экране (функциональные требования)

### 1. Главная `/`

Маркетинговый hero. Должно быть:

- Шапка: лого `alias.online · v2.0` (слева), переключатель темы (справа).
- Бейджи: `v2 · ONLINE PARTY`, `5–32 игрока`.
- Огромный заголовок «АЛИАС / В РЕАЛЬНОМ / ВРЕМЕНИ» (контурная + акцентная строки).
- Подзаголовок про игру.
- **3 кнопки-CTA с моно-подписями снизу:**
  «Создать онлайн-комнату» → `/room/new`, «На одном устройстве» → `/local/new`,
  «Войти по коду» → `/join`.
- Фичи-чеки: «без регистрации», «10 категорий», «работает на любом телефоне».
- Декоративная иллюстрация (карточки слов + таймер) — украшение, не данные.
- ⚠️ **Решено убрать** (в наброске были, заказчик отказался): счётчик «247 online»
  в шапке и нижний «стрип активных комнат».

### 2. История игр

Список прошлых партий + статистика. Элементы:

- Сводка/статы (сыграно игр, угадано слов, % успеха).
- Список карточек игр: статус (LIVE/завершена), дата, режим (online/local), код
  комнаты, команды с цветами и счётом, корона у победителя, кнопки
  «Продолжить» (для незавершённых) / удалить.
- Фильтры/архив (по желанию).

### 3–4. Онлайн-лобби (хост / участник) `/room/[code]`

Хост и участник видят разное:

- **Общее:** код комнаты крупно (`.code-chunk`), QR для приглашения, список
  команд с игроками (цветные), статус «ждём игроков», лимиты.
- **Хост:** управление — создавать/удалять команды, перетаскивать игроков,
  кнопка «Начать игру», настройки партии, «Закрыть комнату».
- **Участник:** видит свою команду, правила, ждёт старта; может сменить команду
  (если разрешено).
- Реалтайм: список обновляется на лету (показывать «онлайн»-точки у игроков).

### 5. Вход по коду `/join`

- Крупный ввод кода из 6 ячеек (`.code-chunk`), либо открытие по ссылке/QR.
- Поле имени игрока.
- Кнопка «Войти». Ошибка «комната не найдена».

### 6. Создание комнаты `/room/new`

- Короткая форма: имя хоста, базовые настройки (можно перенести в лобби).
- После создания → лобби с кодом.

### 7. Команды — шаг 1 (локально) `/local/new`

- Заголовок «шаг 1 из 2».
- Список команд (карточки `.team-card`, тонированы цветом команды) с игроками.
- Добавить/удалить команду и игрока, переименовать.
- Счётчик всего игроков. Кнопка «Далее» → настройки.

### 8. Настройки — шаг 2 (локально) `/local/settings`

- Заголовок «шаг 2 из 2».
- Длительность раунда (чипы/степпер), цель по очкам, штраф за пропуск (тумблер),
  выбор категорий (карточки `.cat-card` с эмодзи и числом слов; всего 10 категорий).
- Кнопка «Начать игру» → создаётся игра.

### 9. Передача устройства `/local/[id]/turn`

- Крупно: чья очередь объяснять (команда + игрок, цвет команды).
- Текущий счёт команд.
- Кнопка «Я готов / Начать раунд» → игровой экран.

### 10–12. Игровой экран `/local/[id]/round`, `/room/[code]/play`

Ядро игры. Состояния (стейт-машина): `PRE_ROUND` (отсчёт 3-2-1) → `ROUND_ACTIVE`
→ `ROUND_REVIEW`. По ролям:

- **Объясняющий:** большая `.word-card` со словом, мега-таймер, прогресс,
  нижняя `.action-bar` с «пропустил» (danger) и «угадал» (accent), счётчик слов.
  ⚠️ **Слово видит только объясняющий** (приватно) — в онлайне остальным НЕ
  показывать.
- **Угадывающий (онлайн):** видит, кто объясняет, таймер, счётчик угаданных, но
  **не само слово**. Карточка «X объясняет».
- **Зритель (онлайн):** как угадывающий, но без участия.
- Пауза доступна (кнопка → оверлей §14).

### 13. Итог раунда `BoldRoundSummary`

- Список слов раунда (`.word-row`): угаданные (accent) и пропущенные (danger).
- Можно поправить статус слова (тап переключает got/skip) до подтверждения.
- Набрано очков за раунд, общий счёт. Кнопка «Дальше» (передача / след. раунд).

### 14. Пауза `BoldPauseScreen`

- Оверлей: «Пауза», таймер заморожен, кнопки «Продолжить», «Завершить/Выйти».

### 15. Финал партии `/results/[gameId]`, `/local/[id]/results`

- Победитель крупно (трофей/корона, цвет команды), подиум.
- Таблица команд с очками, можно график по раундам.
- Кнопки: «Реванш» (новая игра с теми же), «На главную».

## 6. Потоки и навигация

**Локальная игра:**
`/` → `/local/new` (команды) → `/local/settings` → `/local/[id]/turn` (передача)
→ `/local/[id]/round` (раунд + итог) → снова turn для след. игрока → … →
`/local/[id]/results` (финал).

**Онлайн-игра:**

- Хост: `/` → `/room/new` → `/room/[code]` (лобби, код+QR) → «Начать игру» →
  `/room/[code]/play` (цикл раундов) → `/results/[gameId]`.
- Игрок: `/` → `/join` (или по ссылке) → `/room/[code]` (лобби-участник) →
  `/room/[code]/play` → `/results/[gameId]`.

## 8. Роли и приватность (онлайн)

- **Хост** — создаёт комнату, управляет лобби и стартом.
- **Объясняющий** — видит слово приватно (только на своём устройстве).
- **Угадывающие** — видят «кто объясняет» и счётчик, но не слово.
- **Зрители** — наблюдают.
  > Дизайн игрового экрана обязан различать эти роли (особенно: слово показывается
  > ТОЛЬКО объясняющему).
