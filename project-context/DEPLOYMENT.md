# Деплой на сервер

Весь прод — один VPS и один `docker compose`. Пять контейнеров в общей сети,
наружу смотрит только прокси.

---

## Что разворачивается

| Контейнер | Роль | Наружу |
|---|---|---|
| **caddy** | реверс-прокси и TLS | 80, 443 |
| **web** | Next.js: страницы и REST `/api/*` | нет |
| **ws** | Socket.io: реалтайм | нет |
| **postgres** | долговременные данные | нет |
| **redis** | состояние идущих комнат | нет |

Порты Postgres и Redis не публикуются вовсе — до них можно достучаться только
изнутри docker-сети. Caddy держит и обычные запросы, и WebSocket, поэтому web и
ws живут на одном адресе, и CORS между ними просто не возникает.

---

## Требования к серверу

- Ubuntu 24.04 (подойдёт любой дистрибутив с Docker)
- Docker с плагином compose
- Открыты наружу только 22, 80 и 443 (`ufw`), вход по ключу
- **2 ГБ памяти — с оговоркой:** `next build` может не уложиться. Либо добавить
  swap, либо собирать образы локально и пушить в реестр

## Первый запуск

```bash
git clone https://github.com/Cyrikxxx/alias-online.git
cd alias-online

cp .env.example .env
nano .env            # заполнить прод-значения, см. ниже
chmod 600 .env

docker compose -f docker-compose.prod.yml up -d postgres redis
docker compose -f docker-compose.prod.yml run --rm migrate
docker compose -f docker-compose.prod.yml run --rm seed
docker compose -f docker-compose.prod.yml up -d --build
```

Порядок важен: базы должны подняться раньше миграций, а словарь заливается один
раз. `seed` **разрушающий** — он стирает словарь и пересоздаёт его, так что на
живом сервере второй раз его запускать не нужно.

## Переменные окружения

Файл `.env` лежит рядом с `docker-compose.prod.yml`, права `600`. Шаблон с
комментариями — в [`.env.example`](../.env.example).

| Переменная | Значение на проде |
|---|---|
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | свои, пароль длинный |
| `DATABASE_URL` | `postgresql://alias:ПАРОЛЬ@postgres:5432/alias?schema=public` — хост это имя сервиса |
| `REDIS_URL` | `redis://redis:6379` |
| `WS_TOKEN_SECRET` | 64+ случайных символов, **одинаково у web и ws** |
| `NEXT_PUBLIC_WS_URL` | **пусто** — клиент подключится к origin своей страницы |
| `SITE_ADDRESS` | `:80` пока нет домена, иначе `example.com` |
| `WS_CORS_ORIGIN` | адрес сайта целиком, со схемой |

Два места, где ошибиться легче всего:

- **`WS_TOKEN_SECRET` обязан совпадать** у web и ws байт в байт. Не совпал —
  все подключения отваливаются с `invalid token`. Здесь это один файл на оба
  сервиса, так что разойтись негде.
- **`WS_CORS_ORIGIN` не задан** — ws подставляет заведомо несовпадающий origin и
  блокирует всё. Это сделано намеренно: лучше явно не работать, чем тихо
  принимать соединения откуда угодно.

`docker-compose.prod.yml` использует синтаксис `${VAR:?сообщение}` — контейнер
**не стартует** без пароля базы и без секрета. Приложение с дефолтным секретом
выглядит рабочим, а на деле открыто, поэтому дефолтов нет.

Секреты нужны только при запуске: сборка образов их не требует, клиент Redis
подключается лениво.

## Обновление

```bash
./deploy.sh
```

Скрипт делает `git pull --ff-only` → сборку образов → миграции → перезапуск →
чистку старых слоёв и показывает статус. Перед стартом проверяет, что `.env` на
месте.

**Деплой перезапускает ws, то есть рвёт все открытые соединения.** Идущие партии
это переживают: дедлайн таймера дублируется в снимке комнаты, и при следующем
`hello` таймер заводится на остаток, а просроченная фаза доигрывается сразу
(см. [ENGINEERING.md §4](ENGINEERING.md)). Но пауза в несколько секунд игрокам
видна — лучше катить, когда никто не играет.

## Домен и TLS

Пока домена нет, `SITE_ADDRESS=:80` открывает сайт по IP без шифрования.

Когда домен появится:

1. направить A-запись на IP сервера;
2. в `.env` поставить `SITE_ADDRESS=example.com` и
   `WS_CORS_ORIGIN=https://example.com`;
3. `docker compose -f docker-compose.prod.yml up -d caddy`.

Сертификат Caddy получит и будет продлевать сам — отдельного certbot и крона не
нужно.

## Бэкапы

**Это задача владельца сервера, и её никто не делает автоматически.** Раньше
базу резервировал хостинг; на своём VPS — `pg_dump` по крону, с копией **вне**
сервера.

```bash
docker compose -f docker-compose.prod.yml exec -T postgres \
  pg_dump -U alias alias | gzip > backup-$(date +%F).sql.gz
```

Два предупреждения:

- дампы содержат данные пользователей. `*.sql` и `*.dump` закрыты в
  `.gitignore` — держите их вне репозитория и не кладите в папку проекта;
- Redis не резервируется намеренно: там только состояние идущих комнат, которое
  и так живёт сутки.

## Диагностика

```bash
docker compose -f docker-compose.prod.yml ps       # кто жив
docker compose -f docker-compose.prod.yml logs -f web
docker compose -f docker-compose.prod.yml logs -f ws
```

| Симптом | Обычная причина |
|---|---|
| Сайт открывается, но комнаты не работают | `WS_TOKEN_SECRET` разный или `WS_CORS_ORIGIN` не тот |
| `invalid token` в логах ws | секрет разошёлся между web и ws |
| Контейнер не стартует и молчит | не задана обязательная переменная — смотрите логи, там имя |
| Пусто в категориях | не выполнен `seed` |
| Caddy не берёт сертификат | A-запись ещё не разошлась или 80 порт закрыт |
