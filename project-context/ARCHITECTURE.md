# Игротека — архитектура и как всё работает

Документ описывает, из чего состоит проект, как части связаны между собой
и как это разворачивается на сервере. Читай его первым, если вернулся к
проекту после перерыва или открыл его впервые.

---

## 1. Что это

Две игры для компании, живущие в одном приложении:

- **Алиас** — объясни слово, не называя его. Два режима: **онлайн**
  (каждый со своего телефона) и **локальный** (одно устройство на всех,
  передают по кругу).
- **Мафия** — классика с ролями. 5–16 игроков, ведущего заменяет сервер.
  Два режима: обычный (каждый со своего телефона, ночь одна общая) и
  **режим ведущего** для игры за одним столом — ночь идёт по шагам, роли
  просыпаются по очереди, и сайт проговаривает вслух, кому просыпаться.

На главной странице `/` — хаб с выбором игры и полем для кода комнаты.
Дальше зоны не пересекаются: `/alias/*` и `/mafia/*`.

## 2. Монорепо: три пакета

**npm workspaces**. Один git-репозиторий, внутри три независимых пакета:

```
alias-online/
├── apps/
│   ├── web/          → Next.js: страницы + REST API
│   └── ws/           → Socket.io: реалтайм обеих игр
├── packages/
│   └── shared/       → общий код: типы, токены, клиенты БД
├── prisma/           → схема БД + миграции + словарь
├── docker-compose.yml       → локальные базы для разработки
├── docker-compose.prod.yml  → весь прод целиком
├── Caddyfile                → реверс-прокси
├── deploy.sh                → обновление на сервере
└── .env                     → секреты (НЕ в git)
```

### Зачем монорепо

`apps/web` и `apps/ws` используют **одни и те же типы** игровых событий
и **один и тот же секрет** для подписи токенов. В отдельных репозиториях
типы бы разъезжались и появлялись баги «фронт шлёт одно, сервер ждёт
другое». Здесь обе стороны импортируют из `@alias/shared` — поменял в
одном месте, TypeScript ругается везде.

### Что лежит в shared

| Модуль | Что |
|---|---|
| `domain.ts` | типы Алиаса: снапшот комнаты, события раунда |
| `mafia.ts` | типы Мафии: роли, фазы, снапшот, персональный вид, журнал |
| `token.ts` | подпись и проверка WS-токенов (HMAC) |
| `constants.ts` | лимиты и правила Алиаса |
| `snapshot-builders.ts`, `mafia-snapshot-builders.ts` | чистая сборка снапшотов |
| `load-env.ts` | парсер корневого `.env` (общий для web и ws) |
| `server/prisma.ts`, `server/redis.ts` | клиенты БД |
| `server/snapshot-store.ts` | чтение/запись снапшота комнаты в Redis |

`server/*` намеренно **не** реэкспортируются из `index.ts` — иначе Prisma
могла бы попасть в клиентский бандл.

## 3. Из чего состоит прод

Всё крутится на **одном VPS** в Docker, в одной сети:

| Сервис | Роль |
|---|---|
| **caddy** | реверс-прокси, TLS, единственный смотрит наружу |
| **web** | Next.js: страницы и REST `/api/*` |
| **ws** | Socket.io: постоянные соединения, стейт-машины партий |
| **postgres** | долговременные данные: игры, словарь, история |
| **redis** | «горячее» состояние комнат: фаза, таймер, роли |

```
                    Браузер
                       │
                   HTTPS/WSS
                       │
              ┌────────▼────────┐
              │      Caddy      │   :80 / :443
              └───┬─────────┬───┘
        /socket.io│         │всё остальное
              ┌───▼───┐ ┌───▼───┐
              │  ws   │ │  web  │
              └───┬───┘ └───┬───┘
                  └────┬────┘
              ┌────────┴────────┐
        ┌─────▼─────┐    ┌──────▼─────┐
        │ postgres  │    │   redis    │
        └───────────┘    └────────────┘
```

Порты Postgres и Redis наружу **не публикуются** — до них можно
достучаться только изнутри docker-сети.

### Почему web и ws — разные процессы

Next.js обрабатывает запрос и освобождает поток; WebSocket-соединение
нужно держать часами. Разделение позволяет перезапускать фронт, не роняя
идущие партии, — и наоборот.

### Почему две базы

- **Postgres** — источник истины. Что должно пережить перезагрузку:
  пользователи, словарь, сыгранные партии, история.
- **Redis** — состояние идущей комнаты: чья очередь, сколько осталось
  секунд, у кого какая роль. TTL 24 часа.

### Аутентификация WebSocket

Браузер не передаёт cookie в WebSocket-рукопожатие предсказуемым образом,
поэтому связь web↔ws построена на **подписанном токене**:

1. Браузер создаёт или входит в комнату → REST-запрос к **web**.
2. web подписывает токен HMAC-секретом `WS_TOKEN_SECRET`
   (в токене: `userId`, `roomCode`, `role`, `game`, `exp`).
3. Браузер открывает WebSocket, передаёт токен в `auth`.
4. ws проверяет подпись **тем же** секретом.

> `WS_TOKEN_SECRET` обязан быть байт-в-байт одинаковым у web и ws.
> Несовпадение → `invalid token`.

Так как оба приложения стоят за одним доменом, адрес WS-сервера клиенту
не сообщается: `NEXT_PUBLIC_WS_URL` пустой, и браузер подключается к
origin своей же страницы (`/room` или `/mafia`). Схему (`wss://` на
https) socket.io подставляет сам.

## 4. Как устроен реалтайм

`apps/ws/src/` разделён по играм:

```
apps/ws/src/
├── index.ts        вход: два неймспейса — /room и /mafia
├── auth.ts         проверка токена (общая для обеих игр)
├── socket-data.ts  что кладётся в socket.data
├── lib/            дебаунс рассылки
└── games/
    ├── alias/      handlers, services, snapshot, broadcast, типы событий
    └── mafia/      то же + engine (машина состояний) и view (приватность)
```

### Алиас

Машина состояний раунда:
`LOBBY → PRE_ROUND → ROUND_ACTIVE → ROUND_REVIEW → BETWEEN_ROUNDS → FINISHED`.
Слово объясняющему уходит **приватным** emit'ом только его сокету;
остальные видят карточку «X объясняет» и счётчик. Раунд пишется в
Postgres транзакцией при подтверждении итогов.

### Мафия

Фазы: `LOBBY → ROLE_REVEAL → NIGHT → MORNING → DISCUSSION → VOTE →
VOTE_RESULT → LAST_WORD → FINISHED`.

Ключевой момент — **приватность**. В Redis лежит полный снапшот со всеми
ролями, но целиком он не уходит никому. Для каждого сокета
`games/mafia/view.ts` собирает персональный `MafiaView`: свою роль
видишь, чужие — нет; напарников видит мафия; результаты проверок — только
шериф; журнал партии — только выбывшие и зрители. Это единственное место,
где решается, кто что видит, и оно покрыто тестами.

Чистая логика (разыгрывание ночи, подсчёт голосов, готовность фазы)
вынесена в `engine-core.ts` без Redis и сокетов — её можно тестировать.
`engine.ts` отвечает за переходы с побочными эффектами и таймеры.

### Таймеры

Таймеры фаз живут в памяти процесса, а дедлайн дублируется в снапшоте
(`timerEndsAt`). Поэтому перезапуск ws не вешает комнату: при следующем
`mafia:hello` таймер заводится заново на остаток, а если дедлайн уже
прошёл — фаза доигрывается сразу. Это важно, потому что **каждый деплой
перезапускает ws**.

## 5. Переменные окружения

Локально — `.env` в корне (не коммитится). На сервере — `.env` рядом с
`docker-compose.prod.yml`, права `600`. Шаблон — `.env.example`.

| Переменная | Что |
|---|---|
| `DATABASE_URL` | строка подключения к Postgres |
| `REDIS_URL` | строка подключения к Redis |
| `WS_TOKEN_SECRET` | HMAC-секрет токенов, **одинаковый у web и ws** |
| `NEXT_PUBLIC_WS_URL` | адрес ws для клиента; на проде пустой |
| `WS_CORS_ORIGIN` | адрес сайта (белый список CORS для ws) |
| `SITE_ADDRESS` | что слушает Caddy: `:80` или домен |
| `POSTGRES_USER/PASSWORD/DB` | креды базы для контейнера |

Секреты нужны только при **запуске**. Сборка образов их не требует —
клиент Redis подключается лениво, при первом обращении.

## 6. Локальная разработка

```bash
npm install
npm run db:up      # поднять Postgres и Redis в Docker
npm run db:deploy  # применить миграции
npm run db:seed    # залить словарь (10 категорий, 629 слов)
npm run dev        # web :3000 + ws :3001
```

Первый раз можно одной командой: `npm run setup:local`.

| Команда | Что делает |
|---|---|
| `npm run dev` | web и ws одновременно |
| `npm run check` | typecheck + линт + тесты |
| `npm test` | только тесты (vitest) |
| `npm run db:migrate` | новая миграция |
| `npm run db:studio` | просмотр базы |

**С телефона по локальной сети:** открыть `http://<IP-ПК>:3000`.
`allowedDevOrigins` в `apps/web/next.config.ts` уже разрешает приватные
диапазоны, а адрес ws подставляется с тем же хостом (см. `ws-token.ts`).

### Тесты

- `npm test` — два набора сразу.
  - **Серверный и чистая логика** (`*.test.ts`, окружение node): разыгрывание
    ночи, подсчёт голосов, условия победы, состав ролей, приватность
    `buildView`, очки и переход хода у Алиаса.
  - **Клиентский** (`apps/web/tests/*.test.tsx`, окружение jsdom): хуки
    комнаты и таймера, экраны, отдельная проверка гидратации. Сокет там
    поддельный — подменяется единственный модуль `lib/socket-client`,
    навигация Next — заглушкой из `apps/web/tests/stubs`.
- Smoke-скрипты гоняют настоящие сокет-соединения против запущенного
  `npm run dev`:

```bash
npm run smoke:auth  -w @alias/ws   # отказ неавторизованным
npm run smoke:flow  -w @alias/ws   # REST → токен → WS
npm run smoke:lobby -w @alias/ws   # лобби Алиаса
npm run smoke:game  -w @alias/ws   # полный раунд Алиаса
npm run smoke:mafia -w @alias/ws   # партия Мафии на 6 клиентов
npm run smoke:narrator -w @alias/ws # режим ведущего: ночь по шагам
```

`smoke:mafia` заменяет ручной прогон в шести вкладках: раздача ролей,
пауза, ночные ходы, утро, обсуждение, голосование, изгнание, журнал.

`smoke:narrator` проверяет игру за одним столом: порядок шагов ночи,
отказ ходить не в своё окно, скрытый от зала остаток шага и — главное —
что шаг мёртвой роли всё равно случается и занимает заметное время. Без
него смерть доктора стала бы слышна раньше, чем о ней объявят.

## 7. Деплой

### Первый раз на чистом сервере

```bash
# на сервере
git clone <репозиторий> && cd alias-online
cp .env.example .env && nano .env && chmod 600 .env

docker compose -f docker-compose.prod.yml up -d postgres redis
docker compose -f docker-compose.prod.yml run --rm migrate
docker compose -f docker-compose.prod.yml run --rm seed
docker compose -f docker-compose.prod.yml up -d --build
```

### Обновление

```bash
./deploy.sh     # pull → build → migrate → up → prune
```

### Домен и TLS

Пока домена нет, в `.env` стоит `SITE_ADDRESS=:80` — сайт доступен по IP
без шифрования. Когда домен появится: направить A-запись на сервер,
поставить `SITE_ADDRESS=example.com` и `WS_CORS_ORIGIN=https://example.com`,
затем `docker compose -f docker-compose.prod.yml up -d caddy`. Сертификат
Caddy получит и будет продлевать сам.

### Что нужно на сервере

Ubuntu 24.04, Docker с compose. Открыть наружу только 22, 80 и 443
(`ufw`), вход по ключу. Если памяти 2 ГБ — добавить swap, иначе
`next build` может не уложиться; альтернатива — собирать образы локально.

**Бэкапы — это теперь ваша задача:** `pg_dump` по крону с копией вне
сервера. Раньше это делал хостинг.

## 9. Известные ограничения

- Комната, которую бросили недоигранной, остаётся в статусе `IN_GAME`;
  на игру это не влияет, но в БД копится мусор.
- Если объясняющий в Алиасе выпал на экране итогов раунда, раунд можно
  только бросить, закрыв комнату: принудительного подтверждения у хоста
  нет.
- Таймеры рассчитаны на **один** инстанс ws. Горизонтально масштабировать
  его без внешнего планировщика нельзя.
- `npm run lint` падает с давними ошибками `react-hooks` в 14 файлах.
  Это не регресс, но и не почищено.
- Звук конца раунда и реакции-эмодзи в онлайне намеренно вырезаны.
