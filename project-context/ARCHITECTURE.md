Из чего состоит проект, как части связаны и где что искать. Читать первым, если
вернулся к проекту после перерыва или открыл его впервые.

Рядом лежат: [ENGINEERING.md](ENGINEERING.md) — почему принято именно так,

## 1. Что это

Две игры для компании в одном приложении:

- **Алиас** — объясни слово, не называя. Онлайн (каждый со своего телефона),
  локально (одно устройство на всех) и втроём (круг из шести ходов).
- **Мафия** — 5–16 игроков, ведущего заменяет сервер. Обычный режим и **режим
  ведущего** для игры за одним столом: ночь идёт по шагам, роли просыпаются по
  очереди, сайт проговаривает вслух, кому просыпаться.

Полные правила и все числа — в [GAMEPLAY.md](GAMEPLAY.md).

На `/` — хаб с выбором игры и полем для кода комнаты. Дальше зоны не
пересекаются: `/alias/*` и `/mafia/*`.

## 2. Монорепо: три пакета

**npm workspaces.** Один репозиторий, внутри три независимых пакета:

```
alias-online/
├── apps/
│   ├── web/          Next.js: страницы + REST API
│   └── ws/           Socket.io: реалтайм обеих игр
├── packages/
│   └── shared/       общий код: типы, токены, клиенты БД
├── prisma/           схема БД + миграции + словарь
├── scripts/          импорт словаря
├── project-context/  документация
├── docker-compose.yml       локальные базы
├── docker-compose.prod.yml  весь прод
├── Caddyfile                реверс-прокси
├── deploy.sh                обновление на сервере
└── .env                     секреты (не в git)
```

### Зачем монорепо

web и ws используют **одни и те же типы** событий и **один и тот же секрет**
для подписи токенов. В отдельных репозиториях типы разъезжались бы, и появлялись
баги «фронт шлёт одно, сервер ждёт другое». Здесь обе стороны импортируют из
`@alias/shared` — поменял в одном месте, TypeScript ругается везде.

### Что лежит в shared

| Модуль | Что |
|---|---|
| `domain.ts` | типы Алиаса: снимок комнаты, события раунда |
| `mafia.ts` | типы Мафии: роли, фазы, снимок, персональный вид, журнал |
| `token.ts` | подпись и проверка WS-токенов (HMAC) |
| `constants.ts` | лимиты и правила Алиаса |
| `trio.ts` | круг из шести ходов для игры втроём |
| `mafia-narration.ts` | реплики ведущего — сочиняет сервер |
| `snapshot-builders.ts`, `mafia-snapshot-builders.ts` | чистая сборка снимков |
| `load-env.ts` | парсер корневого `.env`, общий для web и ws |
| `server/prisma.ts`, `server/redis.ts` | клиенты БД |
| `server/snapshot-store.ts` | чтение и запись снимка комнаты в Redis |

`server/*` намеренно **не** реэкспортируется из `index.ts` — иначе Prisma могла
бы попасть в клиентский бандл.

## 3. Из чего состоит прод

Всё крутится на одном VPS в Docker, в одной сети:

```
                    Браузер
                       │
                   HTTPS/WSS
                       │
              ┌────────▼────────┐
              │      Caddy      │   :80 / :443
              └───┬─────────┬───┘
        /socket.io│         │всё остальное
              ┌───▼───┐ ┌───▼───┐
              │  ws   │ │  web  │
              └───┬───┘ └───┬───┘
                  └────┬────┘
              ┌────────┴────────┐
        ┌─────▼─────┐    ┌──────▼─────┐
        │ postgres  │    │   redis    │
        └───────────┘    └────────────┘
```

| Сервис | Роль |
|---|---|
| **caddy** | реверс-прокси, TLS, единственный смотрит наружу |
| **web** | Next.js: страницы и REST `/api/*` |
| **ws** | Socket.io: постоянные соединения, машины состояний партий |
| **postgres** | долговременные данные: игры, словарь, история |
| **redis** | «горячее» состояние комнат: фаза, таймер, роли |

Порты Postgres и Redis наружу не публикуются. Почему web и ws — разные
процессы и почему баз две, разобрано в
[ENGINEERING.md §1–2](ENGINEERING.md).

### Как web и ws узнают игрока

Личность живёт в подписанной httpOnly-куке `aid`. Куки не передаются в
WebSocket-рукопожатие предсказуемым образом, поэтому web выдаёт подписанный
токен, а ws проверяет его тем же секретом. Подробно — в
[SECURITY.md](SECURITY.md).

Оба приложения стоят за одним доменом, поэтому адрес ws клиенту не сообщается:
`NEXT_PUBLIC_WS_URL` на проде пустой, и браузер подключается к origin своей же
страницы.

## 4. Как устроен реалтайм

```
apps/ws/src/
├── index.ts        вход: два неймспейса — /room и /mafia
├── auth.ts         проверка токена (общая для обеих игр)
├── socket-data.ts  что кладётся в socket.data
├── lib/            дебаунс рассылки
├── services/       уборка брошенных комнат
└── games/
    ├── alias/      handlers, services, snapshot, broadcast, типы событий
    └── mafia/      то же + engine (машина состояний) и view (приватность)
```

### Алиас

`LOBBY → PRE_ROUND → ROUND_ACTIVE → ROUND_REVIEW → BETWEEN_ROUNDS → FINISHED`

Слово объясняющему уходит приватным emit'ом только его сокету; остальные видят
карточку «X объясняет» и счётчик. Раунд пишется в Postgres транзакцией при
подтверждении итогов.

### Мафия

`LOBBY → ROLE_REVEAL → NIGHT → MORNING → DISCUSSION → VOTE → VOTE_RESULT →
LAST_WORD → FINISHED`

Ключевое — **приватность**. В Redis лежит полный снимок со всеми ролями, но
целиком он не уходит никому: для каждого сокета `games/mafia/view.ts` собирает
персональный `MafiaView`. Это единственное место, где решается, кто что видит,
и оно покрыто тестами.

Чистая логика — разыгрывание ночи, подсчёт голосов, готовность фазы — вынесена
в `engine-core.ts` без Redis и сокетов. `engine.ts` отвечает за переходы с
побочными эффектами и таймеры.

### Таймеры

Живут в памяти процесса, но дедлайн дублируется в снимке (`timerEndsAt`).
Поэтому перезапуск ws не вешает комнату: при следующем `hello` таймер заводится
на остаток, а просроченная фаза доигрывается сразу. Это важно, потому что
**каждый деплой перезапускает ws**.

## 5. Данные

**Postgres, 17 моделей.** Основные группы:

| Группа | Модели |
|---|---|
| Словарь | `Collection`, `Category`, `Word`, `WordCategory` |
| Комнаты | `Room`, `Participant`, `RoomCategory` |
| Алиас | `Game`, `Team`, `Player`, `Round`, `RoundWord`, `GameCategory` |
| Мафия | `MafiaGame`, `MafiaPlayerRecord` |
| Общее | `User`, `HiddenGame` |

`HiddenGame` — отметка «убрано из моей истории»: одна таблица на обе игры с
двумя нullable-ссылками, потому что смысл строки один и тот же. Партия при этом
не удаляется — она просто перестаёт показываться тому, кто нажал.

**Redis** — снимок идущей комнаты одним ключом. TTL сутки, у опустевшей комнаты
десять минут. Раз в час фоновая уборка закрывает в Postgres комнаты, которые
сутки не подавали признаков жизни: снимок исчезает сам, а строка `Room` — нет.

## 6. Переменные окружения

Локально — `.env` в корне (не коммитится). На сервере — `.env` рядом с
`docker-compose.prod.yml`, права `600`. Шаблон — `.env.example`.

| Переменная | Что |
|---|---|
| `DATABASE_URL` | строка подключения к Postgres |
| `REDIS_URL` | строка подключения к Redis |
| `WS_TOKEN_SECRET` | HMAC-секрет токенов и подписи куки, **одинаковый у web и ws** |
| `NEXT_PUBLIC_WS_URL` | адрес ws для клиента; на проде пустой |
| `WS_CORS_ORIGIN` | адрес сайта, белый список CORS для ws |
| `SITE_ADDRESS` | что слушает Caddy: `:80` или домен |
| `POSTGRES_USER` / `PASSWORD` / `DB` | креды базы для контейнера |

Подробности по каждой — в [DEPLOYMENT.md](DEPLOYMENT.md).

## 8. Известные ограничения

Честный список — он полезнее списка достижений.

- Таймеры рассчитаны на **один** инстанс ws. Горизонтально масштабировать его
  без внешнего планировщика нельзя.
- Если объясняющий в Алиасе выпал на экране итогов раунда, раунд можно только
  бросить, закрыв комнату: принудительного подтверждения у хоста нет.
- Вёрстка не покрыта автотестами — headless-браузера в проекте нет.
- Звук конца раунда и реакции-эмодзи в онлайне намеренно вырезаны.
- Нагрузку никто не мерил: сколько комнат держит один инстанс ws — неизвестно.
